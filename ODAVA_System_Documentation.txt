======================================================================
ODAVA Core - On-Device AI Vulnerability Analyzer
System Architecture and Working Process Documentation
======================================================================

1. OVERVIEW
ODAVA (On-Device AI Vulnerability Analyzer) is a desktop application built with Electron, React, and TypeScript. It is designed to perform fast, highly accurate, and completely offline static application security testing (SAST) on local codebases. It ensures that sensitive source code never leaves the developer's machine by utilizing a local AI engine.

2. THE TECH STACK
- Frontend: React bundled with Vite for HMR and lightning-fast builds.
- Styling: Custom, zero-dependency Vanilla CSS targeting a premium, glassmorphism aesthetic.
- Backend/Main Process: Node.js (Electron Main).
- Local AI Interop: `node-llama-cpp` enabling GGUF inference directly on the user's CPU/GPU.

3. THE AI MODEL
ODAVA leverages Small Language Models (SLMs) running completely offline.
- Recommended Models: Phi-4 Mini or Gemma 3 Nano. 
  *(These are favored due to their superior local reasoning capabilities and strict adherence to JSON grammar generation, ensuring UI stability and precise remediation advice.)*
- Quantization: Q4_K_M (for optimal speed/memory balance).
- Format: GGUF

4. HYBRID SCANNING ENGINE & FALSE NEGATIVE HANDLING
To maximize performance and prevent context explosion, ODAVA uses a two-phase engine:

Phase 1: High-Speed Static Rule Engine (Pre-Scan)
- The scanner uses highly-sensitive RegEx and AST-based patterns mapped to common vulnerabilities (SQLi, XSS, SSRF, etc.).
- False Negative Mitigation: Phase 1 is designed with extreme sensitivity to *over-flag* potential vulnerabilities. By casting a wide net, we minimize the risk of false negatives. The subsequent noise is handled intelligently by the AI.

Phase 2: Deep AI Enrichment
- ODAVA isolates each flagged snippet and queries the local AI model.
- The LLM assesses the isolated snippet against a strict context schema. If it determines the static rule misidentified a safe pattern, it sets the `isFalsePositive` flag to true, cleanly filtering it from the user's report.
- Contextual memory is wiped before each prompt to prevent hallucinations and keep inference speeds low.

5. PERFORMANCE BENCHMARKS
(Estimates on standard modern developer laptops - e.g., M1/M2/Intel i7)
- Memory Footprint: ~1.5GB RAM usage.
- Static Engine Sweep: < 50ms for a 10,000-line codebase.
- AI Enrichment Rate: ~1.2 to 2.0 seconds per isolated vulnerability.

6. ADVANTAGES
- Privacy: 100% local analysis; zero data exfiltration.
- Speed: Static rules process thousands of lines instantly; AI only evaluates confirmed suspects.
- Accuracy: AI drastically reduces false positives while producing tailor-made remediation strategies.
